# 2.2.0 — safe Postmark webhooks update

## Important response change

Successful webhook requests now return **HTTP 200**, not 202, with the same `["success"]` body. This aligns with Postmark verification. Update tests or external monitors requiring exactly 202. If necessary, temporarily set `POSTMARK_WEBHOOK_SUCCESS_STATUS=202` and rebuild config caches. Old published configuration inherits the default without republishing.

## Compatibility and security

Runtime support remains PHP 8.3+ within PHP 8 and Laravel 12/13. Existing `^2.0` requirements accept this release. Laravel support is now explicitly enforced by Composer; applications outside that documented range must not assume compatibility.

Basic-auth credentials containing `"0"` are now enforced correctly and string comparisons use `hash_equals`. Production-only firewall behavior, the verified IP list, trusted-proxy handling, event API, recipient precedence, nullable IDs, payload fields, synchronous dispatch, and listener exception propagation remain intact. A non-string webhook path now throws an explicit configuration exception.

Development dependencies use Pest 5 and updated analysis/style tooling. Consumers do not inherit these development requirements. Portable PHPUnit 12 harnesses cover PHP 8.3 and Laravel 12.

## Verification and rollout

Locally verified: 12 PHP/Laravel/latest-lowest lanes; 114 tests/368 assertions per lane; automatic discovery and config/route caches; PHP 8.5/Laravel 13 consumers with Symfony 8.1; zero PHPStan level-9 errors; clean audits and Pint; 100% reported source line coverage; 66 focused Pest mutations and four explicit allowlist-removal mutations detected.

Application integration tests and production ingress/monitoring review remain rollout gates. No package persistence, deduplication, migrations, or tenancy policy is introduced. See the release runbook and verification report for scope and limitations.
